# 小说码字助手

原稿由作者写，GPT 帮你理解、推敲和衔接。三栏窗口包含小说与章节仓库、正文编辑区、交流及出处记忆。无需新账号或模型 API Key，使用你现有 ChatGPT 登录。

**当前版本 0.1.1 已实现本机写作闭环，桌面 ChatGPT 的实际安装和主动建议尚需在你的电脑验证。** 浏览器操作、真实 STDIO MCP 协议、当前 ChatGPT 模型的润色与冲突澄清已经分别测试；模拟宿主测试不能替代真实桌面安装。

## 下载与打开

Windows x64 优先下载 [完整包发布页面](https://github.com/1400627710-creator/-/releases/tag/author-writing-v0.1.1) 的 `author-writing-0.1.1-windows-x64.zip`，完整解压后双击 `START.cmd`。完整包包含 Node 和运行依赖，正常启动无需另行安装或联网下载。发布只在原生 Windows 的启动、诊断和安装测试全部通过后执行。

通用源码包在 `releases/author-writing-0.1.1.zip`，它不包含 Node 和依赖。Windows 启动器会检查 Node 版本，缺少合适版本时通过系统 winget 安装 LTS，并继续启动；依赖缺失时会自动修复。macOS/Linux 使用 Node.js 22 或更高版本，可运行 `START.command`。这些依赖不需要新账号。

启动和安装入口在退出前保留结果，日志保存于 `%LOCALAPPDATA%\AuthorWriting\logs`。双击 `DIAGNOSE.cmd` 可运行真实服务、页面、存稿重启自检，输出 JSON 报告；测试数据与作者稿件隔离。遇到报错请提供错误码或该报告，不需要密码。详见 [启动与安装诊断](docs/startup.md)。

如果直接下载源码，启动文件也会完成构建。网络失败时保留报错文本；不要发送登录凭据。源码开发命令：`npm ci`、`npm run typecheck`、`npm test`、`npm run build`、`npm start`。

## 连接当前 GPT

### 桌面插件窗口

1. 先关闭独立窗口的服务终端，避免同时写同一本机仓库。
2. Windows 双击 `INSTALL-GPT.cmd`；macOS/Linux 运行 `INSTALL-GPT.command`。
3. 完全退出并重启 ChatGPT 桌面端，在插件目录选择“我的写作工具”（已有个人目录时沿用原名），安装“小说码字助手”。
4. 新聊天启用此插件，说“打开小说码字窗口”。窗口中发送问题会通过宿主消息能力让当前 GPT 处理，并把回答写回。
5. 若目录或 UI 能力不可用，使用安装脚本生成的 `桌面MCP备用配置.json`，在桌面设置 → MCP servers → Add → STDIO 填入 command、args、cwd，保存并重启。不要同时启用重复的 MCP 服务。

安装脚本先运行本机服务自检，再准备插件和个人目录，保留已有目录及备份。完整包会把 Node 一起复制到插件安装目录，因此安装后的连接不依赖下载文件夹中的 Node。它不代表你的 ChatGPT 账户已经安装成功。网页 ChatGPT 不读取电脑的本地 STDIO 配置；桌面端的 MCP Apps UI 和 `ui/message` 支持仍须实际检查。参考：[本地 MCP](https://learn.chatgpt.com/docs/extend/mcp)、[官方插件结构及个人目录](https://developers.openai.com/plugins/build/plugins)。

### 当前网页 GPT 文件接力

已经保存到账号的“小说码字助手”技能可处理本机窗口导出的请求：

1. 选正文 → 选“问 AI / 润色 / 代笔” → 写要求 → 发送。独立窗口会将请求保留为待办。
2. 点击“导出请求”，把 JSON 上传当前 ChatGPT，调用“小说码字助手”，说“处理这个码字请求，生成可导入回复”。
3. 下载 GPT 返回的回复 JSON，在窗口点击“导入 GPT 回复”。
4. 核对原文、候选和依据后点击“采纳选段”。不采纳不改正文；顶部撤销可恢复。

该路径实际使用当前对话模型，免 Key；文件传递需要作者操作，不能称为自动直连。结构封装程序不会生成小说。如果缺少前文或文风，GPT 应返回具体问题；编辑原问题补充后重新导出即可。

## 日常写作

- 左侧新建小说、导入 TXT/Markdown 章节、重命名和上下排序。各小说的稿件、记忆和有效问题分开保存。
- 中间输入正文，停笔 650 毫秒后自动保存。Ctrl/Cmd+S 保存，Ctrl/Cmd+Z 撤销，Shift+Ctrl/Cmd+Z 重做。失败时保留未保存稿并提供应急文本下载。
- 右侧自由交流；编辑重问会让该问题及其后续旧回答退出有效分支，迟到回复不能写回新稿。
- 润色只改选段的表达，不添原意。代笔可补不改变情节的动作、心理、对白与过渡；样本或意图不足先问。任何语义与文风判断仍由作者核对。
- “学习原稿”让 GPT 按相关原文提取依据；每条记忆有具体出处，推断待确认。指出错误时旧项立即停用，纠正内容经作者确认再使用。
- 受影响的出处变为失效；未改动的出处跟随修订和位置更新。AI 候选不会自动成为作者样本；可以选段点击“认可为文风样本”。
- 主动建议默认关闭；宿主具备消息能力时可开启。前台新增段落并停笔 30 秒后最多一条，五分钟最多一次，手动请求优先。模拟协议已验证调度，真实桌面的自动模型调用未验证。
- “导出本书 / 批量导出”生成 UTF-8 文本；“备份工程”保存正文、出处记忆、来源标记等 JSON，恢复时创建独立工程，不覆盖现有小说。

## 存稿位置与边界

Windows 默认 `%LOCALAPPDATA%\AuthorWriting`；macOS/Linux 默认 `~/.author-writing`。`state.json` 是主档，`state.previous.json` 是上一份有效提交；`novels/<小说ID>/<章节ID>.txt` 为自动重建的纯文本副本。章节文件名用 ID，名称保存在工程中。

纯文本副本供阅读与导出；请在窗口编辑，直接改 TXT 不会覆盖主档。主档损坏时恢复有效备份并保留损坏文件。记录最近 40 次保存的撤销版本；完整备份应另存一份。

主稿保存在本机；发送或上传给 GPT 的片段仍由在线模型处理，可能留在 ChatGPT 会话中。工具管理自己的聊天分支，不删除 ChatGPT 原生历史。只绑定本机地址，校验网页来源；代码发布清单排除小说、聊天、运行状态和凭据。

详见 [实际验证范围](docs/verification.md)。
