# 后续工作思路

以这份 GPT 初始版 1.0 为代码起点，小喵交接材料用于提取用户认可的需求。每项需求根据当前源码重新实现与验证，不把交接中的推断当作已确认事实。

## 第一阶段：稳定启动、保存和恢复

先验证两个实际入口、首次打开、再次打开、编辑保存和备份恢复。保存状态必须对应成功写入；失败要保留待保存内容，并提供可用的备份通道。改善数据安全时，先增加可验证的备份，涉及存储迁移另列清单确认。

## 第二阶段：制卡、模板和字段闭环

验证新建卡、修改、切卡、切模板及保存重开。模板负责复用版式和适用字段；所有显示名称可编辑。字段按模板区分，同时兼容通用字段；改版式时保护手动覆盖、锁定卡与原始内容。继续保留卡名居中、双击编辑、自由文本、素材与图层的原有能力。

## 第三阶段：双向手动互通

建立可复用的字段映射和稳定编号关联。每次传送先显示新增、更新和冲突；重复操作不生成重复记录，改名后仍能识别原条目。保留未映射字段、来源原文和用户已调整的排版。两个工具分别保存自己的数据，互通由用户手动触发。

## 第四阶段：共用词条和任务界面

词条定义与图片素材分别管理。界面沿用顶部选任务、左侧大类、右侧当前属性的方向，档案和模板有清楚入口。优先减少查找与重复录入，再决定哪些低频功能需要折叠。固定卡框、出血与输出尺寸以用户当前确认的素材和规格为准；参考图先测量再调整。

## GPT 整理方式

GPT 输出带原文引文的字段候选；用户核对后归档。新增字段、修改已有资料先列清单，保留可纠正与追溯的记录。不要求用户在页面填写额外模型 Key。

## 验收与交付

每阶段验证真实使用路径，并在关闭、重新打开后核对结果。自动检查覆盖控件可操作、保存成功、内容恢复与互通结果，不能用函数数量或按钮存在代替功能验证。

交付内容包括对应版本完整代码、修改文件说明、实际检查结果、未验证事项和回滚方式。每次里程碑核对用户完成一张卡的操作步骤、重复工作量和数据恢复能力。
