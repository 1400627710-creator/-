# 小说码字助手 · GPT 一体化版 0.2.0

在 GPT 插件中打开编辑窗口，左侧管理小说和章节，中间码字，右侧交流。使用当前对话模型，不调用模型 API、不索取 Key，不需要本机启动器。

正式原稿、修订、小说仓库、文风样本和可纠正记忆保存在浏览器本机的 IndexedDB。同一设备、同一浏览器中重开会恢复；换浏览器或清理站点数据前请导出完整备份。原 Windows 工具的工程备份可以导入，旧文件不会被覆盖。

新建或直接导入 TXT/MD 原稿后，选中文字即可一键润色、问词，或在右侧说明过渡意图。候选不自动改正文；作者采纳后可撤销、重做。原问题可以编辑重问，旧分支及过时回复不会覆盖新稿。自动学习的记忆须有精确出处，作者纠正先停用旧项，修正经确认才成为正式依据。代笔缺少文风或情节意图时先问作者。

开启“停笔后给小建议”后，仅在编辑窗口可见、有焦点、写入新段落、停笔至少 30 秒、已保存且没有待办时发送一条请求；同一小说至少间隔五分钟。关闭窗口后不会继续发送模型请求。

## GPT 连接

本项目通过 Sites 的正式 MCP 连接发布为私有插件，提供 writer_open 的全屏、全局入口和会话入口。连接后窗口通过宿主消息接口提交当前选段与必要上下文，由当前 GPT 调用 writer_finish 回答。界面使用 MCP Apps SDK 1.1.2；实际呈现取决于宿主提供的能力。

服务器不保存正式原稿或完整小说数据库。回复通道只保存随机请求标识、版本、公钥、权限摘要和短期密文，采用 RSA-OAEP/SHA-256 包装 AES-256-GCM 密钥。私钥与读取权限留在本机；作者窗口接收、核对版本后确认删除通道。通道 20 分钟后拒绝使用，过期记录在后续请求时清理。提供给当前 GPT 的选段、样本和上下文仍由在线模型处理。

## 开发与检查

npm ci → npm run typecheck → npm run build → npm test → npm run validate。Worker ESM 构建将窗口嵌入单个 worker/index.js，无需运行时安装依赖。部署资源通过 .openai/hosting.json 声明，复用其中的 Site 身份。

自动检查包含原稿版本保护、作者采纳/撤销、纠错确认、浏览器存储适配核心、MCP 工具和资源发现、回复加密、权限隔离、重复提交与超时。Node 中的核心及协议测试不等同于实际 GPT 窗口渲染或作者电脑操作；账户连接与完整宿主流程须另行验证。

模拟宿主的流程检查使用实际 HostBridge 和 Worker，覆盖窗口提交、加密候选回写、作者采纳、撤销和存稿恢复，并验证旧待办不挡新回复、通道注册成功但网络超时后仍可重试。此模拟检查使用内存持久化替身，不等同于浏览器 IndexedDB 或真实 GPT 消息通道检查。
