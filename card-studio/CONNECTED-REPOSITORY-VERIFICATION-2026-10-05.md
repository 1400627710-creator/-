# CardStudio：两版资料互通交付与自查

2026-10-05，北京时间。

本次交付为 Studio 3.0.0-beta7、Community 1.4.0 和持久化线上公共资料仓库。设计原则仍是高效、共创、简洁。

## 怎样使用

1. 解压私人版包，先从旧版保存 .cardstudio 项目，再关闭旧版服务窗口。首次启动双击“安装并启动.bat”，以后双击“启动卡牌工具.bat”。需要 Node.js 22 以上。
2. 新版顶部直接打开“词条库”或“素材库”。“公共”读取线上已发布资料；“我的”是当前项目自己的资料；“待审核”接收社区词条和图片。
3. 首次点击“连接管理员”，用建立该公共仓库的 ChatGPT 账号登录，并点击连接私人版。之后发布和审核无需手动配置网址或管理密钥。资料库提供断开管理员连接。
4. 打开原 .cardstudio 项目，在“我的”选择词条或图片，点击“发布到公共仓库”。多个词条可用“发布全部词条”，确认后按批上传。
5. 社区入口：[打开在线社区版](https://cardstudio-community-hub.tells-route3b.chatgpt.site/community/)。发布完成后，另一台电脑刷新词条库或素材库就能查看。无需搬运 JSON 或重新制作社区 ZIP。
6. 社区用户在“我的”创建词条或添加图片，登录后点击“提交到私人版审核”。私人版待审核区可查看完整设计、先加入自己的资料、采用并发布或不采用。通过审核后进入公共库。
7. 下载版社区工具也能投稿：点击提交会打开在线窗口，带入所选资料；登录跳转后恢复，确认提交。离线制卡和 PNG 导出仍可用。

如果旧服务仍占用 8794，新启动器会使用空闲端口并显示新地址。浏览器自动保存按地址隔离；改用端口后，需打开此前保存的项目。关闭旧服务再启动新版可继续使用原地址。不要把新端口的空项目当作旧资料丢失。

## 为什么公共库首次还是空的

真实词条和素材保存在你的电脑和项目中，程序包没有这些用户资料。本轮没有把验证夹具当作正式内容填入公共库。首次在新版打开原项目并主动发布，即可将实际设计放入线上仓库。库空、网络失败和使用缓存有不同提示。

## 本次更正与实现

此前 Beta 6 / Community 1.3.0 只共享本机 shared-data，或通过文件和离线 ZIP 传递资料。将它称为跨版本在线互通是错误的。现在两版读取同一个线上目录，社区投稿写入同一服务，私人版通过授权审核并发布。

词条保存名称、颜色、分类、标签、完整定义、检索别名、示例与设计说明。素材保存图片原文件、分类、说明、尺寸和内容哈希。公共数据和图片持久化；旧作品固定使用已采用的本地内容，不随公共更新自动改变。

管理权限在服务端校验。发布与投稿只提取公开字段；私人项目、AI 配置、密钥和本机管理会话不会写入公共词条和素材。未审核图片仅投稿作者与管理员可读取。共创署名保留投稿作者。

## 完成后第二遍自查

- 修复刷新覆盖成功提示，避免投稿和审核完成后看不见结果。
- 修复离线版带入资料登录后的 ID 和选中状态恢复，避免重复建立同名草稿或误选另一词条。
- 验证仅删除配置不足以确保测试通道立即失效，随后从生产代码彻底移除测试管理员入口；线上复查确认旧凭据不可用，并注销验证会话。
- 验证旧版占用端口时新版选择独立端口，健康接口与准确版本通过后才打开页面。
- 验证重新部署后词条、素材元数据、版本、图片原文件和私人版连接会话保留。
- 验证图片读回与原文件逐字节一致、同名更新冲突拒绝、重复提交幂等、超限不发生部分覆盖。
- 验证并保留旧项目、词条导出、共享素材和离线 PNG 导出兼容性。

当前环境没有运行 Windows 原生双击 BAT，也没有进行真实 ChatGPT 登录页面的人工点击。托管浏览器预览能力不可用，线上页面已做 HTTP 检查；客户端界面在独立测试服务中运行浏览器检查。以上边界不以模拟测试冒充实际登录验证。

生产验证资料已撤下公开目录。公共仓库的使用不依赖这台开发电脑继续开机。
