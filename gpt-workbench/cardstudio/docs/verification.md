# 1.0.3 继续核对窗口层级与消息回声（2026-10-19 UTC）

1.0.2 发布后，真实打开工具返回新版请求结果，生产日志记录新版 resources/read，但没有收到真实窗口 uiReady。同期仍有网站数据请求 401 和顶层登录路径 404；不能据此宣布用户窗口恢复。登录路径由平台管理，本轮没有添加替代登录或绕过身份校验。

继续核对发现：明确标为 MCP 的资源仍依赖 iframe 层级判断，非 iframe 的资源可能误走网站数据请求；同窗口消息回声可能被误认成相同编号的响应。现在 MCP 标记直接决定接入方式，响应必须携带 result 或 error；普通网站预览仍按上一节隔离。

- 修改 `lib/ui-surface.mjs`、`ui/main.mjs` 与 `tests/connection.test.mjs`：资源身份优先，拒绝将自身请求回声作为响应；相应 MCP、服务和界面版本更新至 1.0.3。
- 22 项自动检查全部通过；类型检查、自包含构建通过。
- 只读合成夹具在非 iframe 的同窗口消息环境、禁止网络和 eval 的 CSP 下，实际完成握手、原编辑器初始化及就绪回执；2 份档案、2 张卡与映射均正确。该项是隔离浏览器测试，不代表真实原生客户端验收。
- `docs/connection-top-preview.jpg` 记录上述同窗口模拟结果。临时 QA 页面发布前删除。
- 真实 ChatGPT 宿主仍以实际窗口和真实就绪回执为准，不能由请求结果或模拟回执代替。

# 1.0.2 窗口接入修复与自检（2026-10-19 UTC）

## 用户可见问题与证据

用户在 ChatGPT 内打开时看到“拒绝连接”或“无法打开 打开卡递统一工作台”。生产服务仍返回工作台 HTML 和 MCP 工具结果；日志同时存在未登录数据请求（401）和登录入口失败（404）。这些响应不能证明应用窗口可用，也不能单凭它们确定浏览器拒绝连接的唯一原因。

代码核对发现普通网页 iframe 被当作 MCP 应用、显示模式放错元数据位置、登录链接缺少顶层跳转。浏览器另行复现按钮样式覆盖 hidden 属性。这些已知接入缺陷均已修复；没有改变项目格式、数据库结构、原数据或旧工具。

## 本轮修改文件

| 文件 | 修改内容 |
|---|---|
| `lib/mcp.ts` | 显示模式置于标准 `openai/ui`，清理旧元数据别名及不合规范入口属性；资源列表与读取使用一致声明；打开结果改为 requested；增加不含用户内容的接入日志 |
| `lib/ui-surface.mjs`, `ui/main.mjs` | 明确区分 MCP 资源、普通网页预览及独立网站；普通预览不握手或请求私人数据；实际初始化后发送只读就绪回执 |
| `ui/index.html` | 正确的 ChatGPT 插件入口；网站登录在顶层跳转；普通预览提供独立标签页入口 |
| `ui/style.css` | hidden 属性稳定隐藏元素，避免登录按钮或其他隐藏控件被显示样式覆盖 |
| `scripts/prepare-ui.mjs`, `lib/workbench-html.mjs`, `app/workbench/route.ts` | 同一 UI 分别生成 MCP 与网站标记，网站路由不再返回 MCP 标记 |
| `lib/service.ts` | 只读 uiReady 回执，不创建项目；保留身份验证 |
| `tests/connection.test.mjs`, `tests/service-entry.ts` | 新增窗口类型、资源声明、入口、请求/就绪区分、无数据写入及未授权拒绝回归 |
| `README.md`, `docs/verification.md`, `docs/connection-preview.jpg` | 接入方式、验证证据与模拟宿主截图 |

## 已完成验证

- 21 项自动检查全部通过，包含原有归档、映射、同步、ZIP 及服务往返，以及新增 3 项窗口接入检查。
- TypeScript 类型检查、自包含 UI 构建通过。
- 浏览器使用只读合成夹具模拟 MCP 宿主；实际自包含资源在禁止外部连接、禁止 eval 的 CSP 下完成 ui/initialize、编辑器初始化和 uiReady，显示 2 份档案、2 张卡和 2 条关联；卡片集可点击切换。页面来源范围内未见脚本/CSP 报错。
- 普通网站放进 iframe 时立即显示正确插件入口，不发送 MCP 握手；登录按钮保持隐藏。
- 模拟宿主及夹具仅供本机预览，发布前删除；没有向生产项目写入测试内容。

## 真实宿主验证边界

上述浏览器是隔离模拟宿主，不是用户的 ChatGPT 客户端。真实工具调用成功仅证明服务收到请求；真实窗口完成与否，以实际就绪回执或可见宿主界面为准。发布后的线上结果另行核对，不把模拟测试写成真实宿主验收。

# 1.0.1 修复与自检记录（2026-10-18 UTC）

## 本轮复现与修复

| 问题 | 修复与实际验证 |
|---|---|
| 撤销记录跨项目残留 | 浏览器复现：在甲项目编辑后，乙项目仍可撤销。现在切换、恢复或接收外部更新时重置撤销/重做、素材缓存、临时编辑及检查状态；同项目返回再打开仍能撤销，实测已恢复原正文。 |
| 空卡片项目保留旧编辑器状态 | 空项目也完整载入自己的模板、素材与配置。实测从含图项目切到新项目，再制卡、下载备份，素材列表为空，没有混入旧素材。 |
| 删除关联卡后无法补回 | 原规则遇到失效卡片编号会补回卡片并沿用来源关联编号，清除已删除卡的覆盖状态。浏览器实测先删除一张，再生成显示新增 1 张、沿用 1 张；再次执行新增 0 张，总数和关联数均为 2。 |
| 原文校验可被空引文绕过 | 非空字段必须提供有效引文；不存在的输入编号、缺少原文、过长输入与非法故事排序会被拒绝。空表格单元格仍可导入。 |
| 项目切换及刷新竞态 | 项目载入时暂时阻止编辑；最后一次选择生效。刷新返回后再次检查当前项目、版本和未保存修改，丢弃过期响应；恢复缓存按调用时项目编号读取。 |
| GPT 结果可能打开错误项目 | 预览与制卡结果携带明确项目编号；界面初始化前收到的目标项目会保留，初始化后载入该项目。 |
| 空白字段被误报为文字越界 | 检测空白文字槽时不再用占位边框替代实际内容；纯图像/图标字段仍检查其边界。 |
