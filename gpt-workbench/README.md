# 卡递与车卡机 · 本地工作台 1.2

以用户与 GPT 的初始版 1.0 为起点，完善保存恢复、制卡模板和两端手动互通。未采用小喵运行包作为代码基线。冻结的 1.0 仍保存在 GitHub 的 `gpt-baseline-1.0` 目录及同名回滚分支。

## 开始使用

先完整解压。Windows 双击 **卡递启动器.bat** 或 **车卡机启动器.bat**。其他系统用 Chrome 或 Edge 打开对应文件：

- [卡递](cardstudio/CardStudio-Local.html)：制卡、模板、素材、排版、打印与输出。
- [车卡机](novel-archive/Novel-Archive.html)：自由档案、表格、故事版本、关键词和并排对照。

日常使用不需要安装依赖、登录或模型 Key。程序自动保存到当前浏览器，**不会把资料写回 HTML 文件**。保持文件位置与浏览器不变；更新程序或换设备前导出完整 JSON 备份。此代码包不包含你浏览器中的真实卡牌、档案或图片。

## 卡递 1.2

新建项目只提供一张七项基础单位模板。支持单位／法术切换、透明卡框按原图比例适配、卡框与素材统一图层，以及导出排版参数 ZIP 和复制参数。

操作见 [卡递1.2使用说明](docs/卡递1.2使用说明.md)，修改文件及实测记录见 [卡递1.2修改与自检](docs/卡递1.2修改与自检.md)。

## 本版流程

1. 卡递直接新建独立卡片，也可从档案映射批量制卡。
2. “模板与字段”中创建、复制、改名、导入导出和停用模板。字段可适用于全部或指定模板；停用模板保留已有卡面。
3. “与车卡机互通 / 与卡递互通”中主动打开配对窗口，发送当前或全部资料。接收端先核对新增、更新、相同和冲突，再确认写入。改名与重复传送按稳定编号识别。
4. 卡片回传按已有映射对应原档案字段。原始引文保留，改卡产生的文字标明为手动修订；独立卡片也可归档。
5. 两端词条库共用 `cardstudio-glossary-v1` 文件格式，可手动互传定义、别名、示例和设计说明。定义变更默认不覆盖；图片不随词条发送。
6. 车卡机“备份 → 本机保存记录”提供最近 30 次修改前的记录，可预览恢复。卡递继续保留最近 30 次保存记录。

新窗口无法配对时，使用互通面板中的“使用互通文件”；接收不会替换整个资料库。**完整备份恢复**会替换所选项目，界面会单独提示。

## GPT 整理

本地页面本身不运行模型。卡递“整理新资料 → 复制给 GPT”复制原文和指令到当前对话，再将 GPT 返回的 JSON 带回“导入 GPT 结果”。引文通过原文校验并经你确认后归档。车卡机继续支持文字、Markdown 表格和结构化 JSON 的导入预览。

## 源码与构建

需要 Node 22.13+、Python 3 和 pnpm。在本目录执行：

```sh
pnpm --dir cardstudio install
node scripts/build-workbenches.mjs
pnpm --dir cardstudio test
node --test shared/*.test.mjs
node scripts/build-self-check.mjs /path/to/qa-output
```

构建先生成旧编辑器引擎，再生成本地 UI，将两个应用封装成自包含 HTML。卡递的规范源码在 `legacy/`、`lib/`、`ui/`、`local/`；车卡机的规范源码在 `novel-archive/src/index.html`。`novel-archive/plugin/` 是旧插件 1.0.1 快照，本次未更新已安装插件。

浏览器自检页面在本机 HTTP 测试环境打开，使用隔离合成资料库。详细改动和验证见 [更新与自检报告](docs/更新与自检报告.md)。
