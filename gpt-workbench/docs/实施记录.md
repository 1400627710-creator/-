# 卡递与车卡机实施记录

## 当前任务

用户已确认工作顺序并授权持续实施：现状核验、核心流程、手动互通、界面整理。以 GPT 初始版 1.0 为起点，独立分支 `usability-and-exchange`，不覆盖冻结的 1.0 基线。

## 已确认的缺口

- 卡递交付源码缺少构建前生成编辑器引擎的步骤，直接执行本地构建无法从干净源码重建。
- 原档案备份导入会重建已有档案编号；修改后再次导入可能重复，缺少三方冲突判断。
- 两个独立本地页面没有直接手动传送入口。
- 自定义字段尚未按模板区分，模板管理需要补足新建与编辑闭环。

## 实施边界

只使用隔离测试资料。真实数据不自动迁移；保留原数据库名与备份导入兼容性。互通需要用户主动发送和接收端预览确认，不能在后台相互覆盖。

## 技术安排

- 使用稳定来源编号、导入台账和内容指纹判断新增、更新、重复与双边修改。
- 同一个压缩包内两个自包含 HTML，通过用户主动打开的配对窗口传送；校验窗口引用和随机配对码，提供交换文件作为补充路径。
- 两端独立保存，导入只增加或更新选定记录，保留目标端额外字段、行和版本。
- 保持原有编辑器，通过源码生成步骤构建，避免修改生成文件后被下一次构建覆盖。

## 后续检查

模型和存储测试覆盖重名记录、改名、重复传送、双边冲突、版本保护和来回传送；浏览器检查实际控件、保存重开、模板字段和双向接收流程。Windows 与 file:// 的实测限制如实记录。
