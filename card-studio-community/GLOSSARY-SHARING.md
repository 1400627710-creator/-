# Studio / Community 共享词条

统一格式：`cardstudio-glossary-v1`。

| 字段 | 内容 |
| --- | --- |
| `id` / `name` | 稳定编号与正式名称 |
| `color` | 卡面引用与词条标题颜色 |
| `category` / `tags` | 分类与检索标签 |
| `description` | 完整规则定义 |
| `aliases` | 检索别名列表 |
| `example` | 使用示例 |
| `designNotes` | 设计理由与边界说明 |

检索别名用于搜索；卡面仍以正式名称 `[[词条]]` 引用。旧词条缺少新增设计字段时按空值读取，旧版 Studio 词条 JSON 也可导入。文件上限 5MB、5000 个词条，非法 ID、重复 ID/名称和异常字段明确拒绝。

## 同机两版互通

在 Studio Beta 6 的词条库点击“发布到两版词条仓库”，再点击“打开社区版”。社区版直接读取同一份正式仓库，完整显示设计信息。私人版再次发布后，点击社区版“同步私人版词条”。

社区版保存自己的共创词条后，点击“提交到私人版审核”。投稿进入独立队列，只有私人版审核、合并并再次发布后才成为正式词条。正式词条只读；不会包含在“我的词条投稿”中。

## 离线与项目携带

Studio 的“下载含词条的社区版”生成带当前正式快照的独立 ZIP。对方无需安装 Node，打开 `index.html` 就能查看设计、引用词条和导出 PNG。

独立静态网站或离线版的“提交到私人版审核”会导出投稿 JSON；把文件交给私人版，通过“导入共享词条”预览合并。要更新正式库，可使用“导入词条文件”。

正式词条快照随自动保存及 `.cscard` 保留。共创词条属于当前项目，新建项目会清空自己的共创词条；打开另一项目不会自动合并投稿库。初始空词条快照不会覆盖已经导入的正式内容。

## GitHub 中的共同快照

公开仓库 `shared-glossary/glossary.json` 保存正式数据。维护者使用 `shared-glossary/sync-glossary.mjs` 同步该文件与 Community 的在线 JSON、离线快照，再一起提交。Studio 直接导入同一 JSON 即可查看差异和合并。详见公开仓库 `shared-glossary/README.md`。

标准源码包不附加用户的真实私人词条；先在私人版发布，或导入自己的正式快照。两版互通传递的是词条设计数据。
